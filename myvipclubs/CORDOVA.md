# Building My VIP Clubs as a Cordova app

The Angular/Ionic web app is packaged into a native iOS/Android app with
**Apache Cordova**, using **Pushwoosh** for push notifications and
**cordova-plugin-geofence** for venue geofencing.

> The web build is compiled by Angular into `./www`, which is what Cordova
> packages (`content src="index.html"` in `config.xml`). You never edit `www`
> by hand — it is regenerated by `npm run build`.

---

## 1. Prerequisites

- Node 20.19+ / 22.12+ and npm
- Cordova CLI: `npm install -g cordova` (or use the local devDependency)
- **Android:** Android Studio + SDK (platform 34), a JDK (17), Gradle
- **iOS:** macOS + Xcode + CocoaPods (`sudo gem install cocoapods`)
- A **Pushwoosh** account → an Application (gives you the *Application Code*)
- **Firebase** project for Android push (gives `google-services.json` + Sender ID)
- An **Apple Push** key/cert for iOS push (configured inside Pushwoosh)

## 2. Fill in your credentials

1. `config.xml` — replace:
   - `PW_APPID` → your Pushwoosh Application Code (e.g. `XXXXX-XXXXX`)
   - `PW_PROJECT_ID` → your Firebase Sender ID (Android)
   - `widget id` → your real bundle id (currently `com.myvipclubs.app`)
2. `src/app/native/pushwoosh.config.ts` — set the same `appId` / `projectId`.
3. Android: drop your Firebase **`google-services.json`** into the project root
   (referenced by `config.xml` via `<resource-file>`). It is git-ignored.
4. iOS: configure the APNs auth key inside the Pushwoosh control panel.

## 3. Install & add platforms

```bash
cd myvipclubs
npm install

# Cordova reads plugins + platforms from config.xml / package.json:
cordova platform add android
cordova platform add ios          # macOS only
```

`cordova platform add` automatically installs the plugins declared in
`config.xml`:

| Plugin | Purpose |
| --- | --- |
| `pushwoosh-cordova-plugin` | Push registration + receipt (Pushwoosh) |
| `cordova-plugin-geofence` | Native geofences around venues |
| `cordova-plugin-geolocation` | Location permission / GPS |
| `cordova-plugin-device` | Device info |
| `cordova-plugin-androidx-adapter` | AndroidX compatibility shim |

To (re)install a single plugin manually:

```bash
cordova plugin add pushwoosh-cordova-plugin
cordova plugin add cordova-plugin-geofence
```

## 4. Build & run

```bash
# Rebuild the web bundle into ./www, then package + launch:
npm run cordova:run:android      # device/emulator
npm run cordova:build:android    # produce an APK/AAB

npm run cordova:run:ios          # macOS only
npm run cordova:build:ios
```

These scripts run `ng build` first, so `www` is always current. If you prefer
the raw commands:

```bash
npm run build          # ng build  -> ./www
cordova build android
```

## 5. How the pieces connect at runtime

- On `deviceready` (Cordova only), `App` calls:
  - `PushService.init()` — `pushwoosh.onDeviceReady(...)`, `registerDevice(...)`,
    tags the device with the member id, and listens for `push-notification`.
    A tapped push carrying `userdata` like
    `{ "screen": "manager", "memberId": "m1", "venueId": "v2" }` deep-links the
    venue manager straight to the recognition view.
  - `GeofenceService.init()` — arms a geofence around every venue the member has
    access to and calls `pushwoosh.startLocationTracking()` for Pushwoosh
    geozones. On **region ENTER** it fires `VipService.checkIn(venueId)` — the
    same "I'm here" action — which is where you POST to your backend / the
    Pushwoosh Remote API to send the "VIP arriving" push to the venue manager.
- On the web none of this runs (all calls are guarded by `isCordova()`), so
  `ng serve` and the PWA behave normally.

## 6. Permissions notes

- **Android** manifest permissions (fine/coarse/background location,
  `POST_NOTIFICATIONS`) are injected via `config.xml`. Android 10+ requires the
  user to grant **"Allow all the time"** for background geofencing; prompt for
  it in-app before arming geofences in production.
- **iOS** `Info.plist` location usage strings and background modes
  (`location`, `remote-notification`) are injected via `config.xml`. Request
  *Always* authorization for background geofencing.

## 7. Backend (the missing production piece)

This repo ships the client. To actually notify a manager you need a small
service that:

1. stores each member's Pushwoosh token + tags (the app already tags the device),
2. maps venues → the manager/security devices to alert,
3. on a member check-in (button or geofence ENTER), calls the **Pushwoosh Remote
   API** (`/createMessage`) to push the recognition alert (with the `userdata`
   deep-link payload above) to that venue's staff.
